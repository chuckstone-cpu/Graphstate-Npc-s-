Three research threads that never met

A* is the standard; LPA* and D* Lite were built to reuse work when maps change.

Evaluations use random or sensed changes, mostly in robotics. Even experts say it's unclear when D* Lite really beats A*.

Games mostly re-run A*. Operations research studied deliberate blocking for decades, but only from the attacker's side.

Nobody has measured what deliberate blocking does to the cost of incremental replanning.

Three threads: search algorithms, game AI, and operations-research interdiction. They each studied part of the story but never connected deliberate blocking to replanning effort.

Hand over to Arvind: "That missing link is our research gap."

Gap I is the main one. Gap II matters because a weak baseline flatters D* Lite. Gap III is about realism: the numbers come from the same algorithms the game runs, and we look at the worst single replan, not just averages.

One objective, four modules

Measure whether incremental replanning (D* Lite) still saves search effort when an opponent deliberately blocks the NPC's route on benchmark maps, against replan-from-scratch and lazy baselines.

Module 1

The modules run in order: the port is verified first so that every number later comes from code we trust; then the change models, the full experiment, and the statistics.

Methodology

Four planners
BFS restart — blind, replans from scratch
A* restart — Manhattan heuristic, replans from scratch
Lazy A* — keeps its path; replans only if a new block lands on it
D* Lite — searches backward from the goal; repairs only what changed
Main metric
Expansions: cells the search examines. Machine-independent. Time in ms is secondary (Python timing is noisy).
One run = one NPC trip
The saboteur picks a block

Up to C = 12 cells on the NPC's current path; block each in turn, run its own A*; keep the one that lengthens the trip most (ties → closer to the NPC). Numbers = extra steps, computed live.

act every K = 5 steps ≤ B = 30 blocks / trip never the NPC's cell or the goal never disconnects the goal (BFS check) same maps, problems, seeds for every planner own seeded RNG per prankster

Pipeline top: maps → problems → planners × pranksters → runs → logs → statistics.

The run loop: the NPC takes one step at a time. Every 5 steps the prankster may place a block (at most 30 per trip). If it does, the planner is told and replans; that replan is timed and its expansions are logged. Otherwise D* Lite just moves its start.

Saboteur: the numbers on the toy grid are real detour lengths computed by BFS in the browser. The paper's saboteur does exactly this with its own A*; its searches don't count as NPC work.

Fairness: the saboteur reacts to each planner's own path (the opponent watches the NPC), so trajectories may differ slightly. We report path length so this is visible.

Not supported

"D* Lite gives smoother gameplay"

The hitch is the biggest single replan in a run: the freeze a player would feel.

Random changes: D* Lite's hitch is tiny (10.0 / 106 vs lazy 67.8 / 510). Saboteur: means are the same, about 20.4k each (20,442 vs 20,388). The median is lower for D* Lite (1,049 vs 1,697), but a heavy tail of big repairs balances it out.

The paired test favours D* Lite only weakly overall (p = 0.042) and is not significant on street or room. So we do not claim smoother gameplay.

Why it happens, and what it costs

Where the block lands matters (saboteur)

D* Lite stores distances to the goal. A block near the goal breaks most of that stored search; a block far from the goal breaks only a little.

Expansions ≠ time

A D* Lite expansion costs 3–4× longer than an A* one, which cancels its savings in wall-clock time in our Python code.

Same routes, different thinking

The saboteur makes every planner walk 2.8–2.9× the optimum. Only the thinking cost differs.

Consistency  Every significant result points the same way on dao, street and room; no set reverses it.

Distance to goal: within 25 cells of the goal, no advantage (1,387 D* vs 1,370 A* expansions per event). At 100–149 cells, about 7× fewer (2,505 vs 18,441).

Time: per expansion, D* Lite about 54–70 µs, A* 16–18, BFS 3.5–4. Timing noise between identical runs was 6–38%. We don't claim D* Lite is slower, only that the expansion advantage doesn't show up as a time advantage in Python.

Path overhead (steps / initial optimum) under the saboteur: BFS 2.8, A* restart 2.9, lazy 2.9, D* 2.9.

Scope and limitations

Scope
  • 2D grid pathfinding, 4-connected, unit cost
  • 3 benchmark map sets (dao, street, room)
  • Blocking-only changes
  • One greedy saboteur
Limitations
  • Full knowledge: the NPC learns of each block instantly. (Outwit's thief senses within 7 tiles.)
  • Block-only: cells never reopen. (In Outwit, doors unlock, barrels get smashed.)
  • Timing in Python: 6–38% variation between identical runs; a compiled language could change the time ratio.
  • No diagonals; map side capped at 256 (room 512); 24 maps.
  • Greedy saboteur (best single block), not an optimal interdiction plan.
  • It reacts to each planner's own path, so trajectories differ slightly.
  • Heap tie-order verified only on the game's level1 map.
Future work

Each limitation is paired with the Outwit feature it leaves out, where relevant. Future work closes these gaps one at a time: sensing, reopening cells, smarter saboteurs, and real frame-time measurement in the game.
